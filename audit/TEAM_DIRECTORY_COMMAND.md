# Trusted student directory command — Stage 138

Added searchIntakeTeamStudents to the existing guarded invitation dispatcher. No new route, database table, module navigation or permission is introduced. Production still has enabled:false and no trusted source loader; the existing HTTP owner, origin, selected-account and workspace-revision checks apply before the disabled response. Clients cannot enable the service or supply student/identity/source records.

The configured server path loads trusted sources twice, resolves the actual stored intake through the existing identity/academic normalization and DIRECTORY source context, then reuses the established minimum-data search. The current lead needs one current proposal-scoped STUDENT_DIRECTORY_SEARCH grant. Same-batch academic queries enforce exact programme, batch, semester and course; multidisciplinary research uses the approved institutional scope. Existing editable-state and explicit intake opt-in requirements apply. Legacy intakes are not migrated or inferred.

Fields are allowlisted: proposalId, query, filters, offset, limit. Search text requires 2–120 characters, supported filters contain bounded IDs, offset is 0–10000 and limit is 1–20. Raw identity, source snapshots and unrecognized fields are rejected. Results contain only student ID/version, display name, department/programme/batch/semester references and bounded pagination. No contact details, fees, academic marks, person mappings, grants, private intake narrative or raw workspace are returned. Search grants no membership and makes no database/audit write; accepted invitation remains required for participation. Institutional search logging/retention policy is still a production consideration, not silently declared complete.

Two normalized bindings compare actual minimal source contents as well as source versions, identity mapping, academic mapping and workspace revisions; observed changes return a conflict. Both snapshots must independently authorize the lead. This is a read consistency check, not a distributed lock against changes after the second load.
