# Stage159 — optional student mentor suggestion

Student activity intake now offers an optional suggested mentor name (200 characters) and reason (1000 characters). The value is a self-declared preference, not an authoritative person mapping or assignment. It is shown as such in the existing intake summary and authorized mentor-assignment form. No new module, route, table, permission or command was introduced.

The name is free text, avoiding a fabricated institutional mentor directory while MIS sources remain pending. A reason without a name is rejected. Students can clear/change their suggestion while the draft is editable; prior draft/submission versions remain retained. Legacy forms and records without a preference keep their previous shape. Text is escaped in student and staff views.

The assigned reviewer may select a different mentor using the existing authorized assignment process and reason. The selected mentor still accepts or requests reassignment. Suggestion alone does not notify a mentor, disclose the intake to them, grant role/access, create a team/project or authorize execution. Existing current routing and version guards are preserved.

Implementation: existing `prototype/app.js` form/validation/content/summary/assignment display and `server/form-fields.mjs` allowlist. Generated browser and engine files are regenerated by `scripts/prepare-workspace.mjs`.

Validation: `check-intake-mentor-suggestion.mjs` exercises bounds/orphan reason, no-preference compatibility, clearing and immutable history, peer/stale/locked rejection, private projection, independent staff selection and mentor acceptance, no project creation, forged assignment fields and escaped form rendering. Existing intake/mentor checks, TypeScript and build pass. Full candidate results are recorded in `audit/AUTOMATED_BASELINE_STAGE159.json`.

Browser acceptance remains Not run: supported browser control is unavailable. Test fixtures do not establish real institutional mentor authority. MIS/identity/source configuration and Research/faculty first-review integration remain pending; progression and full demonstration data remain deferred. The earlier v178 handover package is a historical baseline and does not include this increment.
