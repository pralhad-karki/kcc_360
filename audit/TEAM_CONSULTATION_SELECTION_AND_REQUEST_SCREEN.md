# Stage181 — Coordinator consultation selection and request screen

Connected the existing controlled consultation request to Dashboard → Activity Intake overview → department selection → confirmed request. Reused the current command bridge and supportRequests history. No new module, SQL schema, route, institutional grant or sender added.

Read commands discover only current reviewed multidisciplinary research proposals within the requesting Research Coordinator's explicit authority and with current accepted mentors. Department options come from the confirmed team roster and approved CONSULTATION_REVIEW assignments. Each participating department needs one available independent active verified representative; aliases are deduplicated. Existing requests exclude the department from initial-request selection. Missing or ambiguous delegation yields no selectable representative. This does not automatically make all departments mandatory.

The coordinator explicitly selects a department/representative, enters responsibility, deliverable, deadline and reason, and confirms. Dates are validated in the form and again by the server. A non-secret selection hash binds the current source/representative and is checked again at save; it conveys no authority. Existing trusted callers without the optional token retain the original request contract. Changed source versions, stale workspace, duplicate targets and revoked authority cannot produce a new request.

The controller validates/escapes display fields and uses the existing actor/snapshot/revision guards, explicit selection, generation/lock ownership and full-workspace refresh only. The request creates REQUESTED; the representative must separately respond. Original mentor acceptance, consultation completion, final approval and execution remain distinct.

Validation: actual dispatcher/SQLite tests cover coordinator-only discovery, accepted mentor, approved representative eligibility, unavailable/conflicting grants, pagination, privacy/no read writes, stale selection tokens, duplicate exclusions and two department requests. Controller VM tests cover selection and confirmation, required data, invalid dates, malformed responses, pagination/empty options, stale account completion, failed refresh and no replay with request/response controllers loaded together.
