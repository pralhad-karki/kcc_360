# W-08 — Activity and reflection publication privacy, review and delivery boundaries

Status: Browser / institutional walkthrough not run; live reviewer/delivery steps currently blocked

Two distinct publication chains: activity listing preparation/review and own reflection request/nomination/editorial/exact consent/independent publishing. No real website sending or institutional grant provisioning is performed by this guide.

Use approved fictional activity/reflection records in designated acceptance scope. Activity listing needs internal activity approval for submission; reflection request needs current verified successful participation and exact final evaluation/reflection binding. Both server reviewer configurations are empty and the shared transport defaults disabled. Record those steps Blocked unless institution-approved identities/assignments and a separately authorized staging environment exist. Do not seed grants, bypass permissions or change secrets. Guide creation adds no requests, approvals, consent or deliveries.

Current lead/student/mentor for preparation and nomination; only explicitly scoped independent activity reviewer, editorial reviewer and publisher for later decisions. Demo title alone grants none. Developer transport fixtures are separate from manual browser/institutional acceptance.

Use one clearly labelled fictional activity listing and one own-student reflection proposal, with no real participant details, images, signatures or private assessments. Course/programme eligibility remains descriptive text, not MIS enrolment enforcement. Public media, registration/payment processing and automatic cancellation banners are outside current implemented listing controls.

## Step A1 — Current activity lead / mentor

Navigation: Dashboard → Projects → approved fictional activity → Overview → Prepare private listing draft

Action: Enter proposed public title/description/category/organizer, intended eligibility combinations, venue/mode, actual event dates/timezone and optional HTTPS registration URL. Save draft.

Expected: Private version retained; no internal descriptions, participants or media copied automatically. Activity deadline is not silently used as event date; incomplete draft may save with warnings.

## Step A2 — Current lead / mentor

Navigation: Same activity → Preview private version → Preview and submit exact draft

Action: Complete required public fields and current source; confirm exact preview and reason, then submit.

Expected: Exact private version SUBMITTED and edit-locked; not website-approved/published. Missing fields, stale version/source or internal approval block submission. Both times may remain unspecified; half-specified times may not submit.

## Step A3 — Explicit independent activity publication reviewer — currently unconfigured

Navigation: Dashboard → Action Centre → Assigned activity publication reviews → activity Overview → Review exact submitted listing

Action: Only in an approved scoped-identity acceptance environment: review exact submitted version, confirm approval fields or return with reason. In current deployment record Blocked; do not assume HoD/notice role rights.

Expected: Current independent activity+submission grant required; author/submitter cannot review own version. Return permits a new corrected version; approval is only for exact current source.

## Step A4 — Explicit current activity reviewer — currently unconfigured

Navigation: Same approved listing → Queue exact approved listing

Action: With approved test assignment only, enqueue once and inspect activity delivery status. Current default deployment is Blocked for this step.

Expected: One immutable minimal approved payload per approval; queued status is not publication. Repeated enqueue does not duplicate the record; stable listing ID persists across corrected versions.

## Step A5 — Current lead / mentor; approved reviewer in controlled branch

Navigation: Dashboard → activity listing overview → existing activity Overview → Withdraw private submission / new revision

Action: Withdraw a submitted/approved test version with reason; revise and resubmit before independent review. Test a controlled changed date/source separately.

Expected: History retained; new version and fresh review required. Unattempted outdated delivery cancels; attempted delivery needs version-specific acknowledged removal. New dates never silently overwrite public approval.

## Step R1 — Student author (s1)

Navigation: Dashboard → Projects → eligible completed activity → Reflections & Evaluation → Prepare publication request

Action: Use own successful verified participation and final independent evaluation bound to current reflection version. Enter proposed public title/text and reason.

Expected: Private DRAFT proposal, separate from official reflection/evaluation. Earlier draft text remains author-only; academic records are unchanged.

## Step R2 — Student author (s1)

Navigation: Same request → Submit for consideration

Action: Check exact current request/source and submit once.

Expected: SUBMITTED immutable version for mentor consideration. Duplicate/stale request rejected; no public consent, editorial approval or publication inferred.

## Step R3 — Current assigned independent mentor

Navigation: Dashboard → Action Centre → Reflection nomination reviews → submitted request

Action: Review submitted proposal only; nominate or decline with reason. Record request/source/mentor version.

Expected: Current nomination routes later consideration; it grants no editor/publisher authority. Mentor transfer invalidates old nomination and requires current review.

## Step R4 — Explicit editorial reviewer — currently unconfigured

Navigation: Dashboard → assigned publication overview / Action Centre → assigned editorial request

Action: Only in approved scoped environment, prepare an edited public version and record current editorial findings. Current deployment is Blocked; earlier private author drafts must not appear.

Expected: Versioned public-content preparation; official academic reflection unchanged. Material editing invalidates old consent; editor grant must match current request and authority.

## Step R5 — Student author (s1)

Navigation: Same request → Preview exact content & choose consent

Action: Inspect reviewed public author name/title/text, audience and permitted use. Choose explicit consent or decline/withdraw without academic consequence.

Expected: Consent binds exact content/source/review version and public purpose; edited text requires fresh consent. Portfolio-link or certificate-status consent cannot substitute.

## Step R6 — Explicit independent publisher — currently unconfigured

Navigation: Dashboard → Action Centre → assigned publishing approval → Record publishing decision

Action: Only with approved publisher identity, independently review exact current reviewed/consented snapshot and approve or decline with reason. Current deployment is Blocked.

Expected: Author/editor cannot self-approve. Current source, nomination, editorial review, exact consent and scoped publisher grant all required; decision retained separately from delivery.

## Step R7 — Explicit current publisher — currently unconfigured

Expected: Private queue does not publish. One delivery per approved version; no private feedback, grades, contacts or academic files in payload.

## Exception checks

- **Default-denied authority:** Inspect reviewer controls as HoD/coordinator/admin/notice publisher with no explicit publication assignment. Expected: No publication review/approval/enqueue rights inferred from titles or other workflows.
- **Private drafts and identities:** Check earlier drafts as mentor/editor and participant/assessment fields in public previews/payloads. Expected: Only permitted submitted/reviewed public content exposed. Eligibility is not a participant list; private academic records/media remain excluded.
- **Self-review and stale grant:** Use isolated tests for author/editor self-approval, wrong scope, expired/revoked assignment and stale version. Expected: No current review, consent/approval reuse or enqueue from invalid authority/source. Live identities are still pending.
- **Consent independence:** Grant only portfolio-link/status-QR consent or edit reflection public content after consent. Expected: No reflection publishing authorization from unrelated consent; changed exact content needs fresh author consent.
- **Update / cancellation / withdrawal:** Change controlled activity dates/status or withdraw request/consent in a designated test branch. Expected: Approval invalidates; stale queued work cancels or attempted work requires acknowledged removal. Automatic public cancellation banner is not implemented.
- **Receiver race and signature:** Run authorized isolated receipt/update/removal fixtures; inspect a real receiver only after separate approved setup. Expected: Wrong signatures/site/version/digest rejected; old responses never restore removed/outdated versions. Simulation is not live receiver acceptance.
- **Academic independence:** Decline publication or withdraw optional consent and inspect academic completion/official records. Expected: No academic progression/completion restriction or deletion of required official history caused by optional publication choice.
- **Browser versus integration result:** Record whether preview/queue UI, live identities and actual website/cache behavior were each exercised. Expected: No Published/Removed or formal acceptance claim based solely on approval/queue/simulation. Keep Blocked inputs and Not run checks explicit.

Record tester/date/timezone, saved site version, role/assignment proof reference without secrets, all source/content/consent/delivery versions, expected/observed result and Not run/Pass/Fail/Blocked. Keep public previews and tokens within approved scope.
