# Own-invitation views and notice sources — Stage 135

2026-10-19. Isolated server-only contracts; no live dashboard, API, notification queue, transport, role grant or existing intake visibility change.

The normalized source adapter adds only INVITATION_READ for the exact latest-round nonlead invitee. Current pending/accepted/declined/withdrawn/cancelled states may be read by that person. INVITATION_RESPONSE remains restricted to its former pending/accepted relationship; a declined/cancelled invitation cannot be accepted again without a fresh round. Lead management and read rights are not turned into invitee rights.

projectOwnTeamInvitationPilot re-normalizes the editable opted-in intake with current identity/roster/masters, checks approved source/grant scope and validates all team source bindings using the existing invitation model. It returns only proposal/version references, team revision, own student/state/version, allowed own actions and bounded basic project title. No peer roster, other invitations, previous team rounds, private purpose/output/reviews, attachments, fee/grade/contact data, grant payload or raw authority is returned. The basic title is an explicit invitation preview field, not public content; future UI must escape it. Staff/lead/stranger cannot use this own-invitation projection. Invalid, stale, changed or disabled sources return one generic unavailable result without diagnostic source disclosure.

This is a latest-round view during editable proposal preparation. It does not introduce historical intake access or project membership after submission; when the intake is submitted, withdrawn, changes scope, loses authority, or the person is no longer currently invited, this projection and its action notice become unavailable. Existing retained database history is not erased. Broader permitted post-submission viewing needs a separately scoped lifecycle projection.

teamInvitationNoticeSourcesPilot emits one minimal action source only for the current pending invitee. Keys bind proposal/team/own-invitation versions, not unrelated peer-response counts, preventing unnecessary renotification. Notices use a generic title without project title or private text. teamInvitationNoticeCurrentPilot recomputes visibility/action eligibility, so stale source links cannot authorize access.

The pure reconciliation helper operates on one trusted recipient's notice arrays only, deduplicates by versioned key, preserves read timestamp, resolves no-longer-pending sources and supersedes older versions when a new invitation round exists. RESOLVED here describes an inactive notification, not completion/approval of the proposal. The helper is not connected to live queues and accepts only server-derived source arrays, never user-provided notification truth. Actual dispatch still needs authenticated actor/person/account mapping and the existing recipient-scoped notification engine. No email/SMS, background timer or broadcast is activated.

check-team-invitation-read-pilot.mjs verifies own-only projection, lead/invalid-identity denial, no peer/private-source leakage, pending notice identity/version keys, accepted/declined/cancelled/withdrawn resolution, revised-team supersession, retained read state, cross-recipient denial and stale/disabled/submitted-source blocking. Existing normalized/atomic save, identity/source, invitation, sandbox and notification tests provide separate regressions. Browser/institutional acceptance remains Not run. Full demonstration data and semester/year progression remain deferred.
