# Stage186 — Controlled research consultation scope confirmation backend

Added confirmIntakeTeamConsultationScope to the existing trusted command bridge. Only the current Research Coordinator with explicit scoped assignment authority may confirm the complete current issued scope, with a reason and explicit confirmation. The current mentor must have accepted. At least one issued department responsibility is required; empty-scope waivers are not implemented. Every latest non-withdrawn department request must be current and ACCEPTED, and the submitted department list must exactly match these requests. This uses the coordinator's chosen requests, not every participating department by default. A declined or pending request cannot be silently omitted; it must be resolved or explicitly withdrawn first.

Confirmation appends teamConsultationScopes history on the existing intake JSON record. It binds current review/mentor authority and cryptographic digests of mentor acceptance and complete current department requests/responses. No old confirmation is overwritten. Duplicate current confirmation is rejected. Changed/new/revised/withdrawn requests, changed responses, mentor changes or authority revocation invalidate the current confirmation. A fresh confirmation appends the next version after prerequisites are resolved. Latest withdrawn requests are excluded only through explicit coordinator reconfirmation of the remaining scope.

Readiness now reports a current confirmed scope and can become READY_FOR_FINAL_REVIEW when existing prerequisites are satisfied. canApprove, approvalRecorded and executionAuthorized remain false. Supporting responsibility acceptance is not completed delivery or final approval. The existing readiness screen was updated only to display confirmed/unconfirmed scope safely; the confirmation form itself remains the next step.
