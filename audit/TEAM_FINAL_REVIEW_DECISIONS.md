# Stage188 — Configured final approval/rejection backend

Added decideIntakeTeamFinalReview through the existing trusted dispatcher. Only the currently configured FINAL_APPROVE person resolved from the frozen route and current approved authority may decide. Both APPROVED and REJECTED require a reason, explicit confirmation, current reviewed proposal and matching version. Approval requires READY_FOR_FINAL_REVIEW: a current accepted mentor and, for research, confirmed current consultation scope with accepted responsibilities. A configured reviewer may reject a reviewed proposal that is not ready for approval. This step does not add return-for-correction/reopening controls.

The decision appends teamFinalReviews on the existing intake JSON, retaining the submitting/reviewed proposal, team, mentor, consultation and scope records. It captures the configured authority, verified actor/stable person, date, reason and a digest of the complete prerequisites. Duplicate decisions and changed references are rejected. Main intake records remain frozen; final status is derived separately. General student projection exposes a minimal historical decision summary and initiating-student feedback while stripping the private decision record/digest. Readiness displays the recorded final decision and always retains executionAuthorized=false.

Shared reviewed-source validation now blocks prerequisite mutations after a recorded final decision. Existing mentor/consultation reads explicitly retain authorized read-only visibility and disable response/withdrawal controls after finalization. Initial request and scope forms disappear. This preserves access to verified responsibilities while preventing edits after sign-off. Controlled activity handoff and permission to start remain separate; no execution project is created.

Reused two fresh source loads, workspace CAS and atomic audit insertion. Added INTAKE_FINAL_REVIEW to the existing metadata codec for unambiguous decision IDs/versions/reasons. No SQL schema, route, grant or institutional provider added. Also corrected scope-confirmation audit metadata stateAfter from REQUESTED to CONFIRMED; the underlying scope record was already CONFIRMED. Existing historical records are not rewritten.

Validation: real same-batch and research fixtures exercise approval, reviewed rejection before prerequisites are ready, role/revocation/reference/confirmation denial, duplicate decisions, immutable prerequisite records, audit rollback/concurrent CAS, source digest tampering, private audit/student projections, final readiness states and read-only prerequisite visibility. Alternate-decision fixture restoration is test setup, not an application reversal. Existing controller checks cover recorded final decisions and read-only finalized mentor/consultation records. Full evidence: AUTOMATED_BASELINE_STAGE188.json. TypeScript/build checked separately. Browser/keyboard and institutional acceptance not run.
