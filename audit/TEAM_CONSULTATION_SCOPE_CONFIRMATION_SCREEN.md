# Stage187 — Coordinator consultation scope confirmation screen

Connected the Stage186 scope command to the existing readiness detail. A current Research Coordinator receives a fresh preview only when the current mentor and all active issued department requests have been accepted and the scope still requires confirmation. The preview lists each department, representative alias, request version, responsibility, deliverable and due date. It does not expose raw source snapshots, stable person IDs, request reasons or private response reasons. Final-review-only users do not receive the preview/form.

The coordinator reviews the complete issued scope, provides a reason and explicitly confirms. A non-secret preview token binds the fresh source and expected scope version. The server rechecks it on both trusted loads before the existing atomic save. A changed accepted deliverable/request or changed authority cannot be confirmed from an old preview. Existing trusted callers without this optional token retain their previous server contract.

The form preserves current actor/snapshot/revision and cache references, modal/generation checks and lock ownership. It validates references, versions, accepted states, dates and preview token; escapes visible data; requires reason/confirmation; verifies the minimal save response; then applies only a fresh full workspace snapshot. Errors require refreshing/checking status rather than automatic retries. Closing the modal after a successful save still synchronizes the current account; stale account completions do not alter the new account or unlock its work.

Successful confirmation updates readiness without granting final approval or execution permission. Existing confirmation history is retained. No new module, route, SQL schema, grant or notification sender added. The institutional source runtime remains disabled until approved providers are configured.
