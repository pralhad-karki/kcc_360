# Atomic team-invitation save — Stage 132

2026-10-19. Isolated save adapter tested with actual SQLite; no live command, endpoint, route or new SQL table. Existing intake, club, notification and session behavior remains unchanged.

The helper uses the same workspace CAS update and commit-token-conditioned audit INSERT pattern as existing service saves. CREATE, REVISE and RESPOND accept only an exact bounded request shape, selected student IDs or a response decision, and expected workspace/team revisions. Request-supplied actor, source snapshots, grants or verification claims are rejected. The authenticated loader provides identity, configuration, source snapshots and workspace. Source configuration remains disabled by default.

An isolated optional teamInvitationsPilot payload sits on the selected intake. The fixture's teamPilotSource descriptor must match the trusted normalized proposal on that same workspace snapshot and match its intake ID/revision. This is a fixture integration contract, not a completed normalizer for existing legacy/demo intakes. Existing stored intake content, student actor mappings and routing must not be migrated or inferred by this helper. Real MIS identity/cohort/subject/authority sources and normalized source binding remain required before live connection.

The helper clones a queued request, reauthorizes from two fresh loader snapshots and compares actor, workspace and source/authority/grant/context bindings before saving. Server time is rechecked but excluded from that equality fingerprint so ordinary clock advancement does not create a false source-change failure. A configuration or source change observed between loads denies before the transaction. This is not a distributed authorization lock: production loaders must coordinate external authority/version changes at commit, especially if they are stored separately from the CAS workspace.

Workspace data and one content-minimized pilot ledger event commit together on the existing transaction. SQL insert failure rolls back both; losing workspace CAS adds no loser audit and preserves the independent winner. Stale/replayed decisions reject; there is no durable request-ID receipt or promise that a lost response is automatically replayed. A client must reload after a conflict or uncertain response. Audit payload is a separate pilot format with action/person/source/version references, not a new complete NFR-006 structured mapping. It contains no student names, private contact/fee/grade text or grant narratives.

Lead responses contain team counts/revisions. Invitee responses contain only their own student ID, state and invitation version plus proposal/team/workspace references—not peer invitations, group counts, raw authority or roster. No public projection, directory endpoint or broader read right is introduced. Confirmations still do not approve a project or grant event/project membership.
