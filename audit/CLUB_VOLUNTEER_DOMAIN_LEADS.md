# Stage 149 — Event volunteer domain-lead appointments

Review findings: individual task mapping, assignee progress/blocker updates, task board, submission, mentor verification, and individual four-domain performance already exist. Selected-volunteer recruitment and controlled roster handoff were added in Stages 143–148. Explicit appointments for event task domains were missing. Recruitment domains such as Marketing and Operations are organizational responsibilities; they are separate from the four CEM assessment domains.

Minimum change: extend the existing volunteer event Overview and shared command pipeline with one versioned domain appointment command. No SQL schema, route, global role or grading changes. Domain IDs reuse the first frozen position ID for each normalized domain name; positions with the same trimmed, case-insensitive domain share one lead.

The current event owner (active event participant and club member) or assigned mentor may appoint, replace or end a lead. Candidates must have a unique current selected application, a recorded roster handoff for that application, active general membership, active event participation, and a position in that domain. Legacy roster presence alone is insufficient. Appointment changes require expected version, reason and confirmation. Stale, duplicate/no-op, out-of-domain, unauthorized or incomplete requests do not write an appointment.

Each version retains student, opening version, state, actor, time and reason. Current status is recalculated against live source, membership and participant outcomes; approval/start/in-progress stages are supported. Historical appointments remain after eligibility loss or explicit ending. Ordinary event participants receive only domain title, latest lead, version, state and current status; private appointment reasons and history remain with existing recruitment readers. Appointment does not grant general event task management, mentor review, event approval, or portfolio verification.
