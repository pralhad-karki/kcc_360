# Intake source adapter — Stage 131

2026-10-19. Disabled by default and disconnected from the live service, engine and static walkthrough. No new endpoint, SQL table, route, grant, command, roster or demo account is created.

resolveIntakeSourceContext establishes a server-only integration seam for the existing isolated directory, invitation and routing helpers. It consumes a trusted resolved identity, server-loaded editable proposal, approved current institutional roster, approved current authority snapshot and server time. It must never be called with request-supplied identity, source snapshots, grants or team records. This validates loaded contracts; it is not an identity provider, signed provenance verifier, institution onboarding flow or live MIS synchronization.

The fixed demo's actor IDs and sandbox grants are not converted into institutional authority. Default configuration is enabled:false, so missing configuration denies. Enabled test fixtures still require an active resolved stable-person/tenant identity, matching institution, versioned approved source IDs with validity windows/approval references, unique stable roster identities, one explicit scoped lead grant and one configured approval policy. Source reference/version checks support stale-context rejection; the future caller must enforce immutable source versions, reload before save and use workspace CAS. Invalid or unavailable sources deny rather than falling back to fictional data.

DIRECTORY, TEAM_MANAGEMENT and ROUTING contexts require the current proposal lead. INVITATION_RESPONSE requires the exact current latest-round invitee stable person, matching proposal/team/scope and current roster version, with a pending/accepted invitation. The lead cannot use that context to accept for invitees. Individual decision validity, retained round/source bindings and previous grant version are additionally checked by the invitation helper; adapters do not replace those guards. ROUTING here prepares an editable proposal's readiness check, not authorization for a staff reviewer to decide a submitted proposal. Staff review/approval permissions remain a later connection.

Returned serverContext is a minimal detached internal input for the existing helpers: proposal identifiers/scope, whitelisted student identity/academic fields, scoped lead grants, relevant reviewer assignments, policy and server time. Private note, fee, grade, contact and grant-reason fields are omitted. This internal roster/grant context must never be returned directly by an API; user-facing output must use the existing minimum-data search or a future invitee-specific projection. The adapter is not copied to public/workspace.
