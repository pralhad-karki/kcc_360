# Stage 200 — Assigned-student evidence submission form

Projects & Activities → existing activity overview now offers Submit evidence for the current student's unblocked, unsubmitted tasks in a started institutional team activity. The server remains authoritative. No route, database schema, grants, source configuration or institutional activation changed.

The fresh task preview displays deadline, expected output, responsibility, evidence requirement and assigned domain criteria. Students explicitly choose new evidence (title, description, optional HTTP/HTTPS source link) or an existing controlled team evidence reference. A separate individual contribution, reason and confirmation are required. New fields must be blank when reusing evidence. Links are stored without fetching them; private-file uploads remain pending.

The form uses readIntakeTeamTaskSubmission and submitIntakeTeamTaskWork. Exact source/task/execution/submission versions and preview token are retained. Successful submission is acknowledged only after a separate workspace refresh proves the expected evidence and contribution, unchanged task criteria/execution/history, source/team/mentor and submitted-but-unverified state. Save-response data is never applied as workspace data. Malformed/stale previews, changed accounts, reset/closed preparation, duplicate clicks and failed refreshes cannot silently replay a submission. An uncertain result asks the student to refresh and inspect the task first.

Submission moves work to Under review, locks progress reporting and does not award completion, scores or achievements. Existing shared evidence is reused without copying another student's contribution. Mentor verification and revision/resubmission remain later increments.

Validation: check-intake-team-task-evidence-client.mjs exercises the controller in VM and performs real trusted dispatcher → SQLite → scoped student-view round trips for new and shared evidence. It covers role/blocked/state entry, escaped content, strict fields and URLs, current criteria, invalid/malformed responses, saved-record reconciliation, duplicate clicks, account resets and failed refreshes. Full regression evidence is recorded in AUTOMATED_BASELINE_STAGE200.json. Actual browser, keyboard and institutional acceptance remain Not run. Live source activation and private uploads remain pending; semester progression stays deferred.
