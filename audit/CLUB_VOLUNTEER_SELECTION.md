Existing internal organizer/assigned mentor/Student Affairs draft readers can inspect this panel. Only an existing club manager or active-member event owner with current event access can decide. Mentor/Student Affairs read authority does not become selection authority.

One explicit reviewClubVolunteerApplication command uses the existing shared endpoint, form allowlist, current workspace CAS and audit path. It requires current opening/source, unique own-per-student application record, exact opening/application revisions, confirmation and a nonempty reason shared with that applicant. A current pending APPLIED record may become SELECTED or NOT_SELECTED. SELECTED additionally requires current active general membership and remaining capacity for that exact frozen position. Other selected records still occupy capacity if membership changes; no automatic removal or replacement occurs.

A decided SELECTED/NOT_SELECTED application can be returned to APPLIED for fresh review with a recorded reason. This retains prior history and releases a selected slot. This correction is available only in the current pre-execution selection path; it does not alter event participation. Direct repeated decisions, stale revisions, withdrawals, unsupported fields, changed source, started events and unauthorized actors are rejected. A reviewer cannot decide their own application. The current prototype actor check is not a claim of verified institutional person/alias authorization; real account/grant integration remains pending.

Current feedback is included only in the applicant's own minimal opening/application projection, without other applicants or reviewer identity. Existing authorized organizer-level readers retain their internal review access. Displayed text is escaped.
