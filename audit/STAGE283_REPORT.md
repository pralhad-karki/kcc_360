## Bounded plan and changes

Address the two reproduced audit findings before continuing storage cutover preparation: guard authenticated demo writes with the current selected session generation; replace remaining character-based workspace limits with the same UTF-8 byte policy. Reuse existing state transitions, private file storage, consent/source checks, optimistic revisions and atomic audit batches.

- `server/service.ts` adds `readSessionProof()`, returning the current actor and persisted updated_at. Existing `readSession()` still returns the actor string, preserving its callers and read-first behavior. Malformed stored timestamps fail closed with a generic 503; valid historical ISO values need no migration.
- Selecting a demo persona advances its existing ISO timestamp strictly, even under a frozen/backward clock or rapid switch away/back. The timestamp is now also a monotonic session generation, not an exact wall-clock claim. A compare-and-swap on the previous actor/timestamp protects concurrent selections, with at most three attempts before a 409. Unknown personas remain rejected; owner authentication is unchanged. No session record is reset.
- Every changed generic engine command now includes subject, actor and session timestamp in the workspace UPDATE predicate. This replaces the previous conditional actor-only check for two commands. File uploads and authenticated portfolio/reflection share creation/revocation use the same captured proof in their UPDATE predicate. A mismatch yields no candidate workspace/file metadata/audit rows; the existing file cleanup removes a candidate object after a rejected save.
- `server/workspace-write-policy.mjs` is a pure shared byte-budget helper with the existing 2,000,000-byte limit. The main service, file upload, authenticated shares, disabled anonymous reflection responses, mock cohort ledger and internal email ledger reuse it. Other already-byte-based pilots are preserved. No remaining `payload.length > 2_000_000` pattern was found in server source. Request, file and spreadsheet limits remain separate policies.
- Anonymous link responses retain their existing token/source/consent rules; no demo session is incorrectly required for them. That feature remains disabled in production code. Internal email transitions remain internal worker operations and do not acquire end-user session authority or activate email sending. Cohort writes already had a generation fence; their byte limit is corrected without changing progression policy.

## Six-rule review and remaining limits

The new byte policy is framework/database independent. Existing controllers, business workflows and schema are preserved. This narrowly modifies parameterized predicates in the legacy D1 write path; it does not pretend that those services have already moved behind ORM repositories. Existing raw-SQL/driver coupling and the generated legacy engine remain architecture debt. Domain/repository separation, generic errors and portable JSON contracts from Stages 280–281 remain in place. No PostgreSQL schema or driver is installed. Existing D1 batch atomicity is retained; no network request, lock wait or authority load is added inside its transaction. Local SQLite remains WAL in the reused fixture.

These guards cover the owner-demo selected-session model. They do not install institutional SSO, tenant/departments, trusted header provenance, grant revocation providers or role-assignment persistence. Stage 282 TA-01/TA-02 and the broader architectural/operational findings remain open. TA-06's reproduced selected-persona save race and TA-07's remaining character-based workspace guards are addressed locally; this is not closure of all authorization or data-growth risks.

Existing oversized records are retained rather than pruned/reset. A quota-denied share revocation leaves the prior link state unchanged, as explicitly tested. A safe recovery/withdrawal path for already-over-budget legacy state is still required before real consented data rollout; this change does not silently claim withdrawal succeeded. Public demo links and source state are not changed by running these local tests. The 2 MB guard remains an application limit, not accepted hosted capacity.
