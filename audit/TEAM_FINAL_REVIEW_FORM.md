# Stage189 — Final reviewer preview and decision form

Adds one form to the existing Activity Intake readiness detail, visible only when a fresh trusted read identifies the current configured FINAL_APPROVER and no final decision exists. It shows whitelisted submitted proposal fields, confirmed team membership/lead and the existing live mentor/consultation readiness summary. Coordinator-only accounts do not receive the final preview. No new module, schema, route, authority source or permissions are introduced.

The reviewer must choose Approve or Reject without a default, enter a reason and explicitly confirm. Approve is offered only for READY_FOR_FINAL_REVIEW; rejection remains available for reviewed but unready proposals. Backend authority and readiness checks remain mandatory. Terminal decisions remain read-only. Approval does not create an execution project or authorize work to start.

The form sends the current proposal/review/submission references, expected final-history version, workspace revision and a SHA-256 preview token bound to the frozen submission/review, mentor and consultation/scope history and configured final authority. Both fresh server stages recompute and validate the supplied token. The optional token extends the existing command without breaking trusted legacy callers; workspace CAS, independent fresh-source validation and atomic audit remain unchanged for all callers. No private source snapshots, stable person IDs, financial details or mentor assessment narratives enter the final preview.

The browser controller validates the minimal command result and applies only a separately fetched fresh complete workspace. Context, modal, revision, queue and generation guards reject stale work. A failed or ambiguous save/refresh instructs the user to refresh and check status; it does not automatically replay a decision. Account changes cannot apply an old result or unlock another account's operation.
