# Isolated, unrated monitoring-review pilot

Status: automated logic pilot only. Not a live workflow, authenticated service, faculty evaluation, rating system, or institutional acceptance. No routes, engine commands, permissions, dashboard links, storage migrations or seed records were added.

## Reuse and scope

`server/monitoring-review-pilot.mjs` consumes an exact approved academic-plan item using the existing plan IDs, version, owner and item fields. APPROVED, IN_PROGRESS and COMPLETED are accepted because the existing plan progress state is derived. Original plan and supplied inputs are never changed. A later plan revision does not rewrite an earlier review; supplying another version or changing the selected item blocks source-dependent transitions.

This follows the existing pure permission/resource adapter pilot pattern. It is deliberately excluded from live routes and workflow generation. The additional policy helper is necessary to exercise monitoring rules without expanding student-evaluation semantics or installing premature live permissions. Production integration must authenticate the caller, load trusted stable person identities, authorize the exact record/evidence, load the correct historical approved plan, enforce confidentiality, perform CAS persistence and enforce uniqueness. The helper's supplied assignment is a synthetic contract, not an authenticated authorization mechanism. It must never be taken from a browser request as authority.

## Implemented behavior

- Draft creation requires an approved plan/item and explicit subject, submitter and independent reviewer person IDs. No title-derived roles. Same person cannot approve through another actor alias; callers must resolve aliases to stable person IDs with the existing identity adapter.
- SAVE_DRAFT creates immutable content revisions. Review period, achievement explanation and versioned verified evidence references are validated. Numeric zero and missing actual achievement remain distinct. Missing achievement or a numeric variance requires a reason. No automatic effectiveness or final rating is derived.
- SUBMIT locks the current version. Reviewer begins review and returns or approves with a reason. Returned content is revised into a new version; previous submissions and decisions remain in history.
- Output completion and effectiveness are separate reviewer findings. An effectiveness conclusion other than NOT_ESTABLISHED requires current verified outcome evidence. An approved review can legitimately record effectiveness NOT_ESTABLISHED.
- Stale revision, changed plan, inactive/revoked/changed assignment, wrong person, non-monotonic decision time and stale evidence reject the affected command without mutating its input.
- Corrective actions require an assigned owner, valid deadline and expected evidence. Reviewer cannot assign themselves an action they would close. Only its owner updates progress; an independent reviewer verifies current follow-up evidence before closure. Reopening retains closure history and requires another progress update before reclosure.
- Summary exposes limited fields only to explicitly scoped synthetic participants, never raw notes or feedback. Current review/evidence validity is separate from historical APPROVED/VERIFIED_CLOSED states. Overdue follows Nepal's calendar day and does not erase a deadline or history.

## Example and verification

`check-monitoring-review-pilot.mjs` clones existing fictional AP101 v1 / PI101 into an approved in-memory fixture. The real seed remains Draft, and no live records are written. It tests missing/zero/positive achievement, variance, outcome evidence, return/resubmission, version and role denial, independent approval/closure, freshness, reopening, Nepal midnight, minimized summaries and unchanged plan/assignment inputs.

The existing plan, resource/identity/permission and student-evaluation workflows remain separate. Review acceptance, real authority, feedback confidentiality, faculty criteria/weights, appeals and authenticated multi-role sessions are still pending. No official academic marks, faculty ratings, certificates, MIS/LMS exports, website delivery or progression are affected.

### Isolated monitoring save adapter — concurrency and atomic audit
Added server/monitoring-save-pilot.mjs, disconnected from live routes/services and the browser sandbox. Reuses existing kcc_workspaces payload/revision/commit_id and kcc_server_audit schema; no migration or table added. An authenticated trusted loader is required twice: prepare and recheck immediately before transaction. Strict request fields prevent actor/authority/evidence-verification injection. Workspace and review revisions guard concurrency. Server-computed request fingerprints and receipts inside the review prevent duplicate application; conflicting reuse is rejected, while a legitimate retry returns its original commit receipt after fresh authorization. SQL batch combines revision-conditional workspace update with commit-token-bound audit insertion. Audit records stable person, exact plan/item/review/assignment/authority versions, request correlation and decision reason; raw achievement narratives are not copied into audit metadata. Response contains receipt/status only, not raw workspace data.
