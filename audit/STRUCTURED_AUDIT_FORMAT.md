## Minimum format

server/audit-record-format.mjs serializes a strict KCC360_AUDIT_METADATA version 1 envelope suitable for the existing ledger record TEXT field. Metadata includes correlation/workspace/demo-actor/action/time, before/after workspace revisions, an explicitly nullable institutional ID, mapping completeness, a minimal record reference with optional version/state changes, and a controlled reason reference/status. New envelopes reject extra fields. IDs are bounded machine references, states are bounded codes, and reason references point to an approved versioned record field rather than copying confidential reason text. Unknown institutional identity remains null; a workspace label is not silently converted into a verified institution.

MAPPED means the record reference is supplied; it does not certify institutional identity, complete state history or authorization. Null record versions/states remain unknown, not inferred. UNMAPPED explicitly keeps record null and does not invent a reference. A future trusted command mapper must derive these fields from actual before/after records and independently validate any reason reference. This codec validates shape, not reference existence, role authority, semantic truth, signatures, retention or completeness across commands.

## Backward-compatible reads

readAuditRecordMetadata accepts legacy bounded machine record strings and null without changing stored values. Old text receives no fabricated states, reason or institution. Recognized structured envelopes are strictly validated; when a ledger row is supplied, identity/workspace/action/time/revision/correlation must match that row. Unknown versions and malformed recognized envelopes fail closed. Unrelated JSON from existing monitoring/club pilots is identified as another format and its body is withheld, not misinterpreted or exposed. Unrecognized legacy prose is unavailable to this minimized reader; the original database content remains untouched. This helper grants no permission to inspect any audit record and performs no rendering.

## Stage 120 — First trusted command mapping

server/audit-command-map.mjs maps only saveCVDeclarations, using trusted engine before/after snapshots and supplied commit context. It validates the actual declaration shape, own-student identity, one-version increment and changed declaration content. Creation uses an unknown/null prior version; edits and cleared sections retain their version transition. States remain null because CV declarations have no workflow-state field; no approval state is invented. Institution remains null. NOT_REQUIRED reason status follows the user-approved declaration rule, not a blanket rule for other commands.

The output is the strict codec envelope with student record reference and versions only. No section names/content, changed text, hashes of private statements, contact information, grades, feedback or reason narratives are emitted. Other student declaration changes and invalid/deleted/malformed versions are rejected. Unchanged declarations (including an invalid/denied command that leaves them unchanged) return NO_CHANGE with no mapped record. Other commands return UNMAPPED without inventing metadata. Ancillary notification reconciliation is not described by this record mapping; a future writer must retain the existing workspace transaction/audit behavior rather than suppressing a changed-workspace event on this mapper result alone.
